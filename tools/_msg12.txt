推送脚本：修非 ASCII 路径被转义、加边界回退与网络重试

三个真 bug，都出在"往 GitHub API 推"这条路上（本机 github.com:443 不通，
只能走 API）。

1. 非 ASCII 文件名被写坏（最严重）
   putTree() 用 `git ls-tree` 的输出解析路径，而 git 默认对非 ASCII 名字
   **加引号并做八进制转义**。脚本把这个字符串原样当路径传给 API，
   于是远端存下的文件名是 `"APK\344\276\246\345\257\237.md"` ——
   名字里真的带了引号和反斜杠，不等于本地文件。
   修复：`-c core.quotePath=false ls-tree -z`，按 NUL 切分，拿到真实 UTF-8。
   实测：旧方式得到 `"docs/APK\344\276..."`，新方式得到 `docs/APK侦察.md`。

2. 边界检测没有回退
   推送靠"远端 tip 的 tree == 某个本地提交的 tree"定位起点。
   上面的 bug 让含该文件的提交两侧 tree 不同，于是找不到起点、直接拒绝推送。
   修复：加两级回退 —— 先沿远端父链（限 60 次）找双方共有的 tree；
   仍找不到就以"单提交"模式把当前整棵树推上去，而不是卡死。

3. 瞬时网络故障
   上传 blob 时遇到 unexpected EOF / TLS handshake timeout 会直接失败，
   且这类错误没有 HTTP 状态码。推送是幂等的（blob/tree 按内容寻址），
   所以加线性退避重试（写 5 次、读 3 次）。
   关键：必须把 "TLS handshake timeout" 也算瞬时 —— 第一版漏了它，
   重试没触发，看起来像"重试没生效"。

另外修一处我自己引入的 bug：单提交模式下把 boundary 设为 0，
而 revList 是 slice(0, boundary) —— 空数组，于是"什么都没推"。
现在单提交模式显式取最新提交。

现状：远端内容已核对正确（树一致、91 文件零差异、路径正确）。
历史因上面的路径 bug 出现过分叉，最新一次以单提交同步，
tip 树与本地 HEAD 完全一致。
